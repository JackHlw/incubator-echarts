柱状图组内排序：dataSet 方案缺陷演示

左侧为 dataSet 前端预排序方案（有缺陷），右侧为 groupOrder 源码方案（正确）。数据来源于真实 BI 业务场景。

缺陷1（堆叠+稀疏数据）：多系列仅部分分类有数据 — 颜色标识丢失 + tooltip 错乱
真实场景：按"业务类型"分组，每个系列（销售漏斗/客户承诺/最佳案例）只在部分分类下有数据。 dataSet 方案排序后，同一颜色在不同分类代表不同系列，tooltip 也只能显示"位置1/2/3"。
对比右图：groupOrder 方案中每个系列保持自己的颜色和名称，只是堆叠顺序按值动态调整。
👉 请将鼠标悬浮在柱子上对比 tooltip 内容。
❌ 颜色/tooltip 错乱

dataSet 方案 — 颜色含义丢失，tooltip 无法识别系列

✅ 正确

groupOrder 方案 — 颜色=系列，tooltip 显示真实名称

缺陷2（非堆叠+稀疏数据）：并排柱状图 — 部分系列仅在部分分类有数据
真实场景：按"所属部门"分组，各行业（新兴行业/金融/教育/能源/零售）只在部分部门有数据。 非堆叠模式下 groupOrder 控制同一分类内并排柱子的左右排列顺序（值大的靠左）。
左图问题：dataSet 方案中同一颜色在不同分类代表不同行业，图例完全失去意义。
右图正确：每个行业保持固定颜色，只是位置按值排序。
❌ 颜色不固定

dataSet 方案 — 非堆叠，颜色随排序变化

✅ 颜色固定

groupOrder 方案 — 非堆叠，颜色=行业

缺陷3（堆叠+大量系列）：极端稀疏 — 大部分系列仅在1个分类有数据
真实场景：按"销售机会所有人"分组，27个阶段系列中大部分只在"刘蕊"这一个分类下有数据，其他分类极度稀疏。 这是 BI 报表中非常典型的长尾数据分布。
左图问题：dataSet 方案需要 27 个"位置槽"，大部分槽位在大部分分类下为空，排序完全失去意义。 而且无法从图表中识别任何有意义的系列信息。
右图正确：groupOrder 方案中每个系列保持身份，排序仅影响堆叠顺序。
❌ 完全不可用

dataSet 方案 — 27个位置槽，信息完全丢失

✅ 正常可用

groupOrder 方案 — 保持系列身份，按值排序

缺陷4：图例交互后排序不更新
操作：点击右图图例隐藏"zly00312"后，剩余两个系列自动重排（值大的靠左）。 左图隐藏"位置3"后，位置1和位置2的数据不会重新排序。
👉 请点击图例尝试隐藏/显示系列。
❌ 不重排

dataSet 方案 — 隐藏后排序固定

✅ 自动重排

groupOrder 方案 — 隐藏后动态重排
